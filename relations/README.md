# 記事相関データと調査ボード

SCP Reader向けの、原典へたどれる関係データ生成処理です。本文の意味やキャラクター間の関係を推測するものではありません。

## 線の意味と精度

| 種類 | 根拠 | 意味しないもの |
|---|---|---|
| references | 実際に取得した記事本文のハイパーリンク | 共演、同じカノン、敵対・所属関係 |
| has_tag | そのページに付与されたタグ | 同じタグの記事同士が物語上関係するという判断 |
| translation_assertion | hreflang付きalternateや明示的なtranslation-source要素 | 番号・slugが同じだけのページの統合 |

ページの同一性はホスト名とページslugで決めます。HTTP/HTTPSと既知の英語支部ドメイン別名を正規化します。数値の番号だけでは同一視しません。SCP-001の提言、各支部の001、EX、Jは別ページです。

既存カタログのurlENは支部独自記事でも機械的に推測されるため、翻訳元の証拠には使いません。実際のurlJPを優先してページを索引化し、翻訳ページは別ノードとして保持します。翻訳の根拠が確かめられるまで「同じ作品」へ自動統合しません。

本文は#page-contentから抽出し、サイトメニュー・前後移動・クレジット・著者欄・ライセンス欄を除外します。実ページの監査で確認したlicensebox22、u-author_blockも除外します。脚注からの参照はfootnoteとして区別します。リンクのないSCP番号、画像ファイル、外部サイト、管理ページ、未作成リンク、自己参照は線にしません。

RuFoundationは公開APIのFTMLリンクを解析します。コード・コメント・前後移動の行を除外します。iframeやFTMLテンプレートの内部、JavaScriptが実行後に作るリンク、単なる文章中の団体名は解析していません。limitationsにも抽出範囲の制約を保存します。取得成功は「すべての関係が判明した」という意味ではありません。

## 実行

Node.js 20以降。通常はnpm ciで依存関係を用意します。

```powershell
# 全支部からバランスよく、未取得・期限切れの500ページを取得
node relations/refresh.js --max-pages 500
# 日本語だけ。0は上限なし。1回の既定実行予算は5時間
node relations/refresh.js --language jp --max-pages 0
# 指定URLを優先して再取得（配列JSON）
node relations/refresh.js --seeds urls.json --max-pages 100 --age-days 0
# 途中終了しても、完了したページの取得記録は残る
node relations/build.js
node relations/validate.js
node relations/preview.js
node --test test/relations.test.js
```

独立取得はrobots.txtを確認し、既定で各ホストに1秒以上の間隔を置きます。最大4ホストを並列処理し、同一ホストは直列です。robots取得不能時は回避せずそのホストを保留します。連続エラー時は当該ホストの処理を打ち切ります。5時間で新しい取得の開始を止め、保存・検証・アーカイブに時間を残します。

## 初回調査の状況

2026-10-28〜29に、対応する全支部カタログから約6.8万ページを索引化し、代表的な記事・各支部の作品など450ページを本文調査しました。**全記事の本文調査は完了していません。** 正確な最新件数はrelations/output/manifest.jsonを参照してください。

ロシアの公開API自体は応答する一方、独立取得でrobots.txtがHTTP 403となったため、そのホストは未調査のままにしています。未調査を「関係なし」と扱いません。イタリア支部にも初回取得失敗の1ページがあり、その状態を記録しています。

確認用のrelations/output/preview.htmlは、ファイルを開くだけで操作できます。ゲームのスキルツリー風に、現在取得できている本文参照の全体を最初から表示します。ドラッグ・スクロール・ピンチで移動と拡大縮小ができ、点を押したときだけ詳細が開きます。全体図を記事の周辺だけに置き換えることはありません。

同じ2ページ間の往復参照は図の1経路へ束ね、詳細では元の方向別の根拠をすべて保持します。タグは生成データに残しますが、この全体表示には出さず、本文の参照へ絞っています。大きな点は参照数の多い記事です。経路の曲がり方や配置は表示上の整理で、架空の作品関係や読む順番の前提条件を追加していません。

既読ボタンで点を光らせられます。この記録はブラウザのlocalStorageだけに保存し、アプリの履歴とは未接続です。未読も含めた全体表示のためネタバレがあり、アプリ組み込み時の扱いは別途必要です。原典・確認時刻・ソース内容のSHA-256は、詳細内の「参照の根拠」から確認できます。

## 更新と失敗時の扱い

- CAPTURE_RELATIONS=1で通常のクローラーを動かすと、記事詳細用に取得したHTMLからpartial-data/relationsへ別ファイルとして保存します。アプリ初回取得用scp-data.jsonは増量しません。
- ロシア語は記事ソースをAPIから取得します。相関取得時は1並列・1秒以上の間隔に制限します。
- 週次scp-crawler.ymlのrelation-graphジョブは、記事カタログの配備終了後に起動します。以前のrelation-source-records成果物を復元し、新しい取得記録を取り込み、検証済みの図とソース記録を成果物として保存します。相関ジョブの失敗が記事カタログ配備を巻き戻すことはありません。
- 手動のRefresh relation graphワークフローでも取得数・支部を指定できます。通常処理と同じconcurrencyグループで、並行実行による履歴の取り落としを防ぎます。
- ソース取得記録は90日保持するGitHub Actions成果物から引き継ぎます。通常の7日キャッシュ失効には依存しません。90日以上実行されず成果物が失効した場合は、取得範囲を再構築する必要があります。長期運用時はバージョニング付きオブジェクトストレージへ同じアーカイブを保存する拡張が可能です。
- HTTPのETag／Last-Modifiedがある場合は条件付き取得します。304は確認日時だけ更新します。本文が正常に再取得できた場合はリンク集合を置換し、削除されたリンクも消します。
- 失敗は前回成功記録を破棄せず、lastAttemptに記録します。図では古い情報として区別し、既定では線を非表示にします。404/410は過去の証拠を残しつつ、そのページの過去の出力線を無効化します。リダイレクト先の別ページを旧ページの本文だと誤認しません。
- 抽出規則を変えたときはEXTRACTOR_VERSIONを上げます。旧抽出結果を最新版と偽らず、再取得対象にします。

## 出力とアプリへの接続

```text
relations/.cache/records/    原典ごとの成功記録と直近試行（Git対象外）
relations/output/
  manifest.json             スキーマ・リビジョン・言語別調査範囲・チェックサム
  revisions/<revision>/
    nodes.jsonl             全ノードとカタログ内の対応情報
    edges.jsonl             全関係とその出典
  chunks/<sha256>.json      256分割した周辺情報
  preview.html              ローカルで開ける対話式確認図
```

ノードIDをUTF-8でSHA-256にし、16進表記の先頭2桁で周辺情報のバケットを選びます。各チャンクにroots、そこへ出入りするedges、周辺ノードの表示用情報neighborsを含めます。スマホが全相関図を一括ダウンロードする必要はありません。チャンク名とチェックサムは内容に基づくため、未変更のチャンクは再利用できます。

ノードのcatalogEntriesには言語と既存itemIdを保持し、将来アプリの閲覧履歴と対応付けられます。ただしこれはカタログの対応情報であり、翻訳の同一作品判定ではありません。本文確認状況とユーザーの既読状態も別です。

ファイルを書き終わりチェックサムを決めた後でmanifestのポインターを原子的に置換します。変更のないリビジョンのファイルは書き直しません。validate.jsで重複・参照先・出典のソース一致・全ファイルのチェックサムを検証します。

コードはリポジトリのライセンスに従います。原典から抽出した関係データにはCC BY-SA 3.0と出典URLを付与しています。作者クレジットが機械的に確認できた場合はノードに保持します。[SCPのライセンスガイド](https://scp-wiki.wikidot.com/licensing-guide)。

現段階ではアプリの既存画面や公開データURLへは接続していません。成果物の公開とFlutter画面への組み込みは、このデータの確認後に行えます。


## 関係の意味と文書の区別

`pageKind` は `scp / log / hub / tale / document`。出版社タグを優先し、URL形式による暫定分類は `basis:url_pattern`、不明は `unclassified` と明示する。支部内で種類ごとに配置を分け、ログは菱形、SCPは丸、ハブ等は四角で表示する。暫定分類は内容の確認を保証しない。

共演・会話、敵対、所属、カノン所属、同じカノン、実験・接触、続編、作成・起源、関連ログの型を定義した。初期検証セットはENの079→682（会話）、682→409（実験）、Follow The Keter内の076-2→682（敵対）、105→Omega-7（過去の所属）、CalmとImmediate ActionsのResurrection所属。確認件数はmanifestと画面に表示し、定義済みの関係すべてが調査済みとはしない。全件調査済みの相関図ではない。

`reviewed-relations.json` に出典URL、対象URL、関係種別、本文の完全一致引用、解釈の注意を登録する。自動処理はその出典の本文に引用が残っている場合だけ関係を生成し、消えれば次の取得成功時に外す。引用一致は解釈の正しさを自動保証しないため、追加時は独立した人/エージェントによる本文レビューが必要。同じカノンは一般タグの共有から作らない。原典が対象人物/物体の所属等を明言しない場合は通常参照に留める。

**登録ルールを変更する際は必ず `EXTRACTOR_VERSION` を増やす。** これにより既存の304応答ではなく本文再取得を要求する。旧v2記録は通常参照として引き続き利用するが意味的関係を補完しない。失敗・404・期限超過は従来どおり非表示/古い根拠扱い。FTMLは現状通常参照のみ。

補遺は確認済みHTML見出しと節内リンクから判定し、「補遺内で参照」と表示する。「作中に登場した」とは断定しない。ログからのリンクも同様。現在HTML構造で確認できる日英中の補遺見出しに限定し、未対応言語・iframe内・変則的書式を推測しない。

APIでは補遺位置はreferences.evidence[].section、文書種別はnodes[].pageKindで表す。補遺参照・ログ内参照はこれらから表示時に導出し、共演や所属などの意味的断定のエッジとは区別する。


カノンは現在、ENの公式パンくず `Canon Hub → Resurrection → 作品` の明示がある場合だけ所属を生成。同じハブへの所属が確認できた作品を詳細欄で「同じカノン」と表示する。全SCPや作品内に登場したSCPへ所属を転写せず、N×Nの派生線も生成しない。他支部・他カノンは未調査であり、類似タグで補完しない。

組織ノードは出典ローカルの `entity:<出典ページID>/<key>`。過去の所属など時間的条件は根拠注記で表示する。別作品の同名組織を勝手に同一世界として統合しない。第三者のTaleに書かれた敵対関係は本文の対象記事を端点とし、根拠文書は別に保持する。本文と異なる出典の記事同士を一般設定として断定しない。


## 全カタログの初回調査

`node relations/full-refresh.js` は全支部のカタログURLを対象に、最大4支部を同時に取得する。同一ホストへの間隔、robots確認、エラー時停止は通常処理と同じ。各支部の上限は24時間。今回の抽出器版で取得済みかつ1年以内の本文はスキップし、途中終了後の再実行でも保存済み記録を再利用する。これは初回網羅調査用であり、通常の鮮度更新は既存refresh.jsで行う。

進捗は `relations/.cache/full-refresh-status.json` と標準出力。全支部のパスが終わるとbuild/validate/previewを実行する。finished_passは全件成功ではなく、取得拒否・通信失敗・未取得件数を別途確認する。意味的関係の登録数は自動では増えず、全記事の敵対・所属等の人手相当の調査完了を意味しない。既存カタログ外の全Taleや全実験ログを網羅する処理でもない。


### ロシア支部のAPI経路（2026-10-29修正）

`robots.txt` は403のHTMLボット確認画面を返す一方、既存クローラーでも利用中の `/api/articles/{pageId}` は認証なしでJSON本文を返すことを確認。ロシア支部の独立取得はこの公開記事APIのみに限定し、HTMLクロールとは取得条件を分ける。ボット確認の突破やHTMLへのフォールバックは行わない。1秒以上の間隔、同一ホスト直列、連続失敗時停止は維持。他支部のrobots確認は従来どおり。

ロシア分のAPI一括取得は、自動承認レビューがプロセス起動コマンドを `blocked by policy` として拒否したため未開始。審査側の詳細理由は返されておらず、API自体が利用禁止と判定されたことは確認できない。再開処理では `--exclude-language ru` を明示しているため、他支部を再開してもロシア分は実行されない。APIの単件応答確認、API対応コードの存在、一括取得の実行状態を混同しない。


### ロシアAPI追加取得の開始と高速化

2026-10-31、ユーザーのAPI全件取得の再依頼を受け、ローカル起動に成功し、実際の取得成功を確認。以前の起動拒否は現在の実行状態を表さない。ログは `relations/.cache/ru-api-parallel.log`、状態は `relations/.cache/ru-api-status.json`。

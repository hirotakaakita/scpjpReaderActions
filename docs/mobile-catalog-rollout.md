# モバイルカタログ v1 の段階移行

Stgでの配信・Android検証を完了し、本番への軽量版データ追加を承認済み。
アプリのストア公開と最低対応バージョンの変更は対象外。

## 配信契約

- 従来の `local-data/scp-data.json`（JP互換）、`local-data/<lang>/scp-data.json`、`meta.json` は維持する。
- 新形式は `local-data/mobile-v1/<lang>/manifest.json` と `catalog-<sha256>.json.gz`。
- UTF-8、整形なしJSON、gzip level 9。manifestのschemaVersionは1。
- `data` はアプリの取り込みに必要なフィールドだけを含み、nullの任意項目を省略する。
- `tagVersion`、`tagFetchStatus`、調査用メタ情報は元データに残す。これらはクローラーの更新・リトライ判定に必要。
- 全文の短縮やタグの削除は行わない。記事ID・更新日時・並び順も変えない。
- manifestには言語、カタログ更新日時、件数、gzip前後のバイト数、SHA-256、ファイル名を記録する。
- ハッシュ付きファイルを先に生成し、manifestを最後に置換する。同じコミットで旧カタログと一緒に公開する。
- 旧metaから更新を検知した際、新manifestの更新日時が一致しなければ従来JSONを使う。

`node mobile-catalog.js [input-local-data] [output-directory]` で生成する。既定の出力は入力配下の `mobile-v1/`。
元データとmetaの日時・件数が一致しなければ生成を失敗させる。既存の配信JSONは変更しない。
Actionsでは辞書適用・漫画フラグ付与・記事ID検証の後、コミット前に生成する。
漫画の公開などで手動でカタログを更新する場合も、この生成処理を最後に実行し、軽量版を同じコミットに含める。
部分的に古い軽量版を残してはいけない。

## 移行手順

1. ローカルで生成・互換性・SQLite取り込み・フォールバックを検証する。
2. レビュー・承認後にStgへ同じコードを適用する。本番は変更しない。
3. Stg対応アプリで初回起動、旧DB更新、言語切替、通信切断、壊れた軽量版を検証する。
   旧アプリでも従来の配信が利用できることを実機で確認する。
4. 承認後、本番Actionsへ追加する。初回は週次実行を待たず、既存カタログから新形式を生成して公開する。
   旧配信と新配信の更新日時・件数・表示値、実URLの取得を確認する。
5. 対応アプリをストアで公開する。バージョン番号は実際のリリースに合わせて決める。
   `app-status.json` は変更しない。
6. `catalog_sync_result` の `catalog_format` (`mobile_v1` / `legacy`)、`catalog_fallback`、
   成功率、parse/store時間、クラッシュを確認する。received_bytesは取得した本体バイト数であり、
   HTTPレベルの圧縮時は通信量と一致しない。manifest分と失敗した試行分も含まない。
7. 全対象ユーザーがストアで更新可能で、実績が安定した場合にのみ強制アップデートを別途判断する。
   軽量化だけを理由に最低対応版を引き上げる必要はない。
8. 旧配信の廃止は別作業とする。強制アップデート判定はapp-status取得失敗時に通常起動へ進むため、
   強制更新設定だけで旧アプリからのアクセスを遮断できるとは考えない。

## 復旧

- 軽量版は配信前・404・不正なmanifest・通信失敗・整合性不一致・JSON/記事解析失敗時、
  対応アプリが従来JSONへフォールバックする。閉じたクライアントは再利用しない。
- どちらも失敗した場合、既存DBはそのまま保持する。言語切替も失敗時に既存データを保持する。
- 問題時は新形式のmanifestを取り下げ、既存JSONへ戻す。既存配信を維持することが前提。
- 強制アップデート後に最低対応版を下げても、旧アプリへ自動ダウングレードされるわけではない。
- フォーマット変更だけでは更新日時やDBバージョンを上げない。既存利用者は次回の内容更新から移行する。

## ローカル検証

```
node --test test/mobile-catalog.test.js
node mobile-catalog.js <既存local-data> <作業用出力>
```

アプリ側の `tool/verify_mobile_catalog_test.dart` で生成物を実際のDartデコーダーに通し、
旧カタログとアプリが利用する全フィールドの一致を検証する。
Stg・本番の既存JSONをテスト用に書き換えない。

```
flutter test --no-pub --dart-define=MOBILE_CATALOG_OUTPUT=<作業用出力> --dart-define=LEGACY_CATALOG_INPUT=<既存local-data> tool/verify_mobile_catalog_test.dart
```
